## 🔴 FIX 3 — "No fields to update" Bug When Saving whatsapp_phone

**File:** `src/pages/AdminDashboard.jsx` — function `saveUserWhatsApp`

Current code (line 494):
```js
await api.updateUser(userId, { whatsapp_phone: edits.whatsapp_phone ?? '', whatsapp_apikey: edits.whatsapp_apikey ?? '' })
```

The problem: `whatsapp_apikey` is being sent in the request body. In `server/routes/users.ts`, the `updateData` object starts with `{ full_name, role, can_view_attendance, profile_picture_url }` — these are always included even if undefined, which means `Object.keys(updateData)` is never empty. So the "No fields to update" check is NOT the issue here.

The REAL cause: the server receives `whatsapp_apikey` in the body but then strips it from the response via destructuring. Meanwhile the frontend state update on line 495 sets `whatsapp_apikey` from `edits` — but `edits` may not have `whatsapp_apikey` defined if the user only typed a phone number, causing the save to appear broken.

**Fix in `AdminDashboard.jsx`:** Since we are using Green API (no per-user apikey needed), simplify `saveUserWhatsApp` to only send `whatsapp_phone`:
```js
async function saveUserWhatsApp(userId) {
  const edits = waUserEdits[userId] || {}
  setWaUserSaving(s => ({ ...s, [userId]: true }))
  try {
    const phone = edits.whatsapp_phone?.trim() ?? ''
    await api.updateUser(userId, { whatsapp_phone: phone })
    setUsers(prev => prev.map(u => u.id === userId ? { ...u, whatsapp_phone: phone } : u))
    setWaUserEdits(e => { const n = { ...e }; delete n[userId]; return n })
    setWaUserTestResults(r => ({ ...r, [userId]: { ok: true, message: '✓ تم الحفظ' } }))
    setTimeout(() => setWaUserTestResults(r => { const n = { ...r }; delete n[userId]; return n }), 2500)
  } catch (err) {
    setWaUserTestResults(r => ({ ...r, [userId]: { ok: false, message: err.message } }))
  }
  setWaUserSaving(s => ({ ...s, [userId]: false }))
}
```

**Fix in `server/routes/users.ts`:** Remove `whatsapp_apikey` from the PATCH handler entirely since Green API doesn't need it per user:
- Remove `whatsapp_apikey` from the destructured `req.body`
- Remove `if (whatsapp_apikey !== undefined) updateData.whatsapp_apikey = ...`
- Remove `whatsapp_apikey: _wak` from the returning destructure — just use `password_hash`

## 🔴 FIX 5 — whatsapp-config.json Saved to Filesystem (Lost on Replit Restart)

**File:** `server/whatsappConfig.ts`

Green API config (`greenapi_instance_id`, `greenapi_token`, `enabled`, `phone`) is saved to `server/whatsapp-config.json`. On Replit, the filesystem resets between restarts, so all settings are lost silently.

**Fix:** Move the WhatsApp config to the database. Add a `whatsapp_config` key to the existing `office_settings` table (or create a new `system_settings` table if one doesn't exist).

Replace `getWhatsAppConfig()` and `saveWhatsAppConfig()` with DB-backed versions:
```ts
export async function getWhatsAppConfig(): Promise<WhatsAppConfig> {
  try {
    const [row] = await db.select({ value: officeSettings.value })
      .from(officeSettings)
      .where(eq(officeSettings.key, 'whatsapp_config'))
      .limit(1)
    if (row?.value) return { ...DEFAULT_CONFIG, ...JSON.parse(row.value) }
  } catch {}
  return { ...DEFAULT_CONFIG }
}

export async function saveWhatsAppConfig(config: Partial<WhatsAppConfig>): Promise<WhatsAppConfig> {
  const existing = await getWhatsAppConfig()
  const merged: WhatsAppConfig = { ...existing, ...config }
  await db.insert(officeSettings)
    .values({ key: 'whatsapp_config', value: JSON.stringify(merged) })
    .onConflictDoUpdate({ target: officeSettings.key, set: { value: JSON.stringify(merged) } })
  return merged
}
```
Make sure `officeSettings` is imported from the schema. Check `shared/schema.ts` for the correct table name and key/value column names.
